## 1. GitHub란 무엇인가

GitHub는 파일을 저장하고 공유하는 플랫폼입니다. 우리 과제에서는 다음 용도로 사용합니다.

- **각 기관이 샘플 현황 파일을 올리는 공간**
- **다른 기관의 진행 상황을 실시간으로 확인하는 공간**
- **파일이 수정될 때마다 변경 이력이 자동으로 기록되는 공간**

> **비유**: 과제 전용 공유 폴더라고 생각하면 됩니다. 단, 누가 언제 무엇을 올렸는지 이력이 모두 남습니다.

## 2. 시작 전 준비 — 계정 만들기

### 2-1. GitHub 계정 생성

> 이미 GitHub 계정이 있다면 이 단계를 건너뜁니다.

1. 웹 브라우저에서 **https://github.com** 에 접속합니다.
2. 우측 상단 **Sign up** 버튼을 클릭합니다.
3. 이메일 주소, 비밀번호, 사용자명(username)을 입력합니다.
   - 사용자명은 `kimm-홍길동` 처럼 기관명을 앞에 붙이는 것을 권장합니다.
4. 이메일 인증을 완료합니다.

### 2-2. 관리자에게 초대 요청

계정을 만든 후, **과제 관리자(KIMM 김재현)**에게 아래 정보를 전달하여 레포지토리 초대를 요청합니다.

```
이름: 홍길동
소속: NNFC
GitHub 사용자명: nnfc-홍길동
이메일: example@nnfc.re.kr
```

관리자가 초대 이메일을 보내면, 이메일에서 **Accept invitation** 버튼을 클릭하여 수락합니다.

## 4. CSV 파일 관리 방식

### 파일 1개에 계획과 완료를 함께 관리

각 기관은 **파일 하나**로 계획 중인 배치와 완료된 배치를 모두 관리합니다. 별도의 `planned` / `completed` 파일을 만들 필요가 없습니다.

배치가 진행됨에 따라 **`status` 필드와 날짜 필드만 업데이트**합니다.

```
계획중  →  제작중  →  완료  →  발송완료
```

예시: SKKU의 경우 월초에 새 행을 추가하고(`status: 계획중`), 제작이 끝나면 `qty_completed`와 `status`를 수정하고, 발송 시 `sent_date`를 기입합니다. 행을 삭제하거나 새 파일을 만들지 않고, **같은 파일에 매월 행을 누적**합니다.

### 업데이트 주기 권장

| 시점 | 할 일 |
|------|-------|
| 매월 1일 | 해당 월 새 배치 행 추가 (`status: 계획중`) |
| 제작 완료 시 | `qty_completed`, `status` 수정 |
| 발송 완료 시 | `sent_date`, `status: 발송완료` 기입 후 GitHub에 업로드 |

### Excel에서 CSV로 저장하는 방법

1. Excel에서 파일 수정 완료 후 **파일 → 다른 이름으로 저장** 클릭
2. 파일 형식을 **CSV UTF-8 (쉼표로 분리) (*.csv)** 로 선택
3. 기관 파일명 그대로 저장 (예: `skku_samples.csv`)
4. "CSV 형식으로 저장하시겠습니까?" 팝업이 뜨면 **예** 클릭

> ⚠️ **파일 이름을 반드시 지정된 이름으로 저장하세요.** 다른 이름으로 저장하면 대시보드에 자동 반영되지 않습니다.

## 6. 파일 업로드 및 수정하기 (웹 브라우저)

GitHub Desktop 앱 없이 **웹 브라우저만으로** 파일을 올리고 수정할 수 있습니다.

### 처음 업로드하기

1. 본인 기관 레포지토리 주소에 접속합니다.
2. **`samples`** 폴더를 클릭합니다.
3. 우측 상단 **`Add file`** → **`Upload files`** 를 선택합니다.
4. CSV 파일을 끌어다 놓거나 **"choose your files"** 로 선택합니다.
5. 하단 **Commit changes** 섹션에 변경 설명을 입력합니다.
   - 예시: `2026-02 샘플 현황 업데이트 (SKKU 홍길동)`
6. **`Commit changes`** 초록 버튼을 클릭합니다.

> ✅ 파일 이름 옆에 방금 입력한 설명과 업로드 시간이 나타나면 성공입니다.

### 파일 수정하기 (데이터 업데이트 시)

매월 현황이 바뀔 때마다 **같은 파일 이름으로 덮어쓰기**합니다. GitHub가 이전 버전을 자동으로 보관하므로 이전 기록은 사라지지 않습니다.

**방법 A — Excel에서 수정 후 재업로드 (권장)**
1. 로컬에 저장된 CSV를 Excel로 열어 수정합니다.
2. 위 '처음 업로드하기' 과정을 그대로 반복합니다.
3. 같은 파일 이름으로 올리면 자동으로 덮어씌워집니다.

**방법 B — 웹에서 직접 수정 (소량 변경 시)**
1. `samples` 폴더에서 해당 CSV 파일을 클릭합니다.
2. 우측 상단 **연필 아이콘(✏️ Edit this file)** 을 클릭합니다.
3. 내용을 직접 수정합니다.
4. 하단 **Commit changes** 버튼으로 저장합니다.

> 📌 **이전 버전 확인**: 파일 페이지에서 **History** 버튼을 클릭하면 과거에 올린 모든 버전을 확인할 수 있습니다.

## 9. 자주 묻는 질문 (FAQ)

**Q. 실수로 잘못된 내용을 올렸어요.**  
A. 걱정하지 않아도 됩니다. [6절 수정하기](#6-파일-업로드-및-수정하기-웹-브라우저) 방법으로 파일을 다시 올리면 됩니다. 이전 내용은 History에 보존됩니다.

---

**Q. CSV 파일을 열었더니 한글이 깨져 보여요.**  
A. Excel에서 아래 방법으로 열어보세요.
1. Excel 빈 통합문서 → **데이터** 탭 → **텍스트/CSV에서**
2. 파일 선택 후 **인코딩을 UTF-8** 로 설정 → 로드

---

**Q. 파일 이름을 다르게 올렸어요 (예: skku_samples_2월.csv).**  
A. 대시보드 자동 집계가 되지 않습니다. 정해진 파일 이름으로 다시 올려주세요.

---

**Q. 지난 달 행은 삭제해야 하나요?**  
A. 삭제하지 않아도 됩니다. 파일 하나에 전체 이력을 누적하는 것이 원칙입니다. 대시보드는 `year_month` 필드를 기준으로 해당 월 데이터만 필터링합니다.

---

**Q. `kimm_batch_ref` 같은 다른 기관 ID는 어떻게 알 수 있나요?**  
A. KIMM이 NNFC로 전사 기판을 발송할 때 `kimm_transfer.csv`의 `batch_id`를 이메일로 공유합니다. 또는 대시보드 **📋 상세 추적** 탭에서 확인할 수 있습니다.

---

**Q. GitHub에 로그인이 안 돼요.**  
A. https://github.com/password_reset 에서 이메일을 입력해 비밀번호를 재설정하세요.

---

**Q. 레포지토리 접속 시 "404 Not Found" 오류가 뜨거나 파일이 안 보여요.**  
A. 두 가지를 확인하세요.
- 초대 이메일에서 **Accept invitation**을 아직 클릭하지 않은 경우
- 레포지토리 주소를 잘못 입력한 경우 → [3절 표](#3-우리-기관-레포지토리-찾아가기)에서 재확인

---

**Q. 같은 기관에서 여러 명이 파일을 올릴 경우 어떻게 하나요?**  
A. 기관마다 파일 담당자 1명을 지정하는 것을 권장합니다. 여러 명이 동시에 같은 파일을 수정하면 충돌이 발생할 수 있습니다.

---

**Q. GitHub Desktop 앱을 사용하면 더 편한가요?**  
A. 파일을 자주 올리는 분이라면 https://desktop.github.com 에서 앱을 설치하면 편합니다. 그러나 이 문서에 설명된 웹 브라우저 방법으로도 충분합니다.
